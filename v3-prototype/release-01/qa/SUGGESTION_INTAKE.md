# 候補の受け取りと、毎週の見直し

「候補を教える」で集まったものが Google Drive に自動で届き、Claude が毎週
確認して更新案を出すまでの手順。運用文書であって、配信物ではない
（`qa/` は `.vercelignore` で配信面から除外されている）。

## いまの設計と、変えなければいけないこと

`suggest.html` は意図的に backend を持たない。ページの約束はこう書いてある。

> このページでは保存・計測・個人ごとの推薦を行いません。入力内容は自動送信
> されません。「候補文をコピー」を押した場合だけ、端末のクリップボードに
> コピーされます。公式Xは押したときだけ開きます。

この一文は RC02 の独立監査で確定した文言で、`qa/release_check.js` が
一字一句で守っている。つまり「自動で届く」を実現するには、この約束と
正面から向き合う必要がある。黙って backend を足すことはできない。

## 採る方式: Google フォームへ出るリンク

送信は **Google のページ側で** 起こし、`suggest.html` 自体は何も送らない。

- 利用者が「フォームで送る」を押したときだけ、Google フォームが開く
- 記入も送信も Google のページで行われる
- 回答は Founder の Drive にあるスプレッドシートへ自動で入る
- `suggest.html` からの外部送信は、これまで通りゼロ

構造としては、すでに監査を通っている公式Xのリンクと同じ
（押したときだけ外部が開く）。だから約束を破らずに、開示を1文足すだけで済む。

backend や第三者フォームサービスを置く案は採らない。secret の管理が要り、
ページの性格そのものが変わり、`YOU MUST NOT add external data transmission`
の趣旨からも遠い。

フォームは作成済み。`suggest.html` に「送信フォームを開く」を追加し、開示文も
差し替えた。貼っている URL はこれ。


Founder からは編集用の `/edit` URL を受け取ったが、それを公開ページに貼ると

シークレットウィンドウで一度開いて確認すること。** 「権限が必要です」と出る

`https://docs.google.com/forms/d/e/1FAIpQLS…/viewform` に差し替える。
直すのは `suggest.html` のこの1行だけ。

## Founder にやってもらうこと

Claude は Drive API から Google フォームを作れない。ここだけ人の手が要る。

1. 設問を4つ、いまの `suggest.html` と同じ並び・同じ必須条件で作る

   | 設問 | 種類 | 必須 |
   |---|---|---|
   | 場所・作品の名前 | 記述式（1行） | 必須 |
   | 公式ページのURL | 記述式（1行） | 任意 |
   | 種類 | プルダウン（飲食・喫茶／体験・おでかけ／本・古書／音楽・ライブ／映画・演劇） | 任意 |
   | ひとこと（200字まで） | 段落 | 任意 |

2. フォームの設定で、**メールアドレスの収集をオフ**にする。
   誰が送ったかは要らない。集めない情報は漏れない。
   「回答を1回に制限する」もオフ（ログインを強制しないため）。
3. 回答をスプレッドシートにリンクする
4. そのスプレッドシートを、この Drive フォルダへ移動する

   `03_EDITORIAL_CONTENT_棚と作品 / 候補の受け取り_SUGGESTIONS`
   https://drive.google.com/drive/folders/19u7ywNUNfh-0I3eimsIUyLq-WTWqQeYx

5. シークレットウィンドウでフォーム URL を開き、記入できることを確認する

## 適用済みの開示文

> このページでは保存・計測・個人ごとの推薦を行いません。入力内容は自動送信
> されません。「候補文をコピー」を押した場合だけ、端末のクリップボードに
> コピーされます。送信フォームと公式Xは、押したときだけ開きます。フォームは
> Google のページで、記入と送信はそちらで行います。

元の約束を1つも弱めず、行き先が増えたことだけを足している。
文言確定は独立監査の担当なので、codex 復帰後に確認を通す。

## prefill はしていない

フォームは空で開く。入力済みの文字を query に載せて渡す prefill は、押した
瞬間に文字が外部へ渡ることを意味し、「押したときだけ開きます」で説明できる
範囲を越える。二度書きの手間より、説明できることを優先した。
`release_check.js` が query 付きの form link を FAIL にする。

## 毎週やること

`候補の受け取り_SUGGESTIONS` のスプレッドシートを読み、次を判定する。

毎週の起動は Routine で行う。**これは claude.ai の Routines 画面から作る
必要がある。** Claude Code の側から作った Routine には Google Drive の
connector が引き継がれず、起きても Drive を読めないため意味がない
（2026-08-29 に実際に作って確認し、無意味な週次実行になるので削除した）。

作り方:

1. claude.ai の Routines で新規作成
2. スケジュールを毎週1回にする（日本時間の月曜午前など）
3. connector に **Google Drive** を付ける。これが本体
4. prompt に `qa/SUGGESTION_WEEKLY_PROMPT.md` の中身をそのまま貼る

1. 前回見た行より後の回答だけを見る
2. 各候補を編集契約に照らす
   - 事実として確認できるか（一次情報が公式ページにあるか）
   - `evergreen` にできるか。できないなら `mode: 'current'` として
     `verifiedAt` と `expiresAt` が引けるか
   - Hook が答えを先に言っていないか
   - 図版の権利が clear か。無ければ活字図版で組めるか
   - 既存12件と重複しないか
3. 通ったものを `qa/EDITORIAL_ROTATION.md` の候補欄へ書き足す
4. 判断の記録を Drive のフォルダへ残す

Claude はここまで。棚に載せる差し替えそのものは人の編集で行う。
`YOU MUST NOT merge to main without CEO approval` は毎週の運用でも変わらない。

## 送らないもの

このフォームで受け取るのは、公開されている場所・作品の推薦だけ。
利用者が書いた本文・タイトル・写真・バックアップの中身は、この経路に
一切乗らない。感情書店の本文は端末の中にあり、外へ出さない。

## 1. Product Promise

### 【DECISION】現時点の約束

> **実在する東京の店・場所・体験を、「何これ？」から始めて、事実で裏づけ、公式の行き先まで運ぶ。**

3 つの構成要素:

1. **実在すること** — 架空・生成物を置かない。公式に確認できる対象のみ。
2. **「何これ？」から始まること** — 説明から始めない。Real Media と短い Hook を先に出す。
3. **行き先があること** — 眺めて終わらせず、公式の Action（予約・開館情報・公式ページ）に接続する。

### 約束しないこと（【DECISION】）

- 感情の診断・採点・分析・助言をしない。
- 「あなたに最適」を提示しない（personalization / AI recommendation を持たない）。
- 網羅・検索の完全性を約束しない（有限・編集済みであることが仕様）。

### 【DECISION】価値の候補は 2 本立て（2026-08-26 補正）

| # | 価値候補 | 内容 |
| --- | --- | --- |
| **A** | **Browse / Entertainment Value** | 見ていて面白く、**また新しいものを見に戻りたい**と思う |
| **B** | **Intent Deepening Value** | 興味が深まり、**公式ページ／予約／地図へ進む** |

- **A と B の両方を価値候補として扱う。** B（Official Action 到達）は**必須成功条件ではない**。
- Official Action は**重要指標**だが、**到達しないことだけを理由に Product Kill としない**。
- 【HYPOTHESIS】A・B のいずれが主価値になるかは未検証。Pilot で両方を測る。

### 【HYPOTHESIS】まだ約束にできないもの

- 「知らなかった見方が一つ増える」ことがユーザーにとって**価値として認識される**か。
  → 現時点の根拠は Founder 1 名の反応のみ。**外部検証が必要**。

## 2. User Job

### 【HYPOTHESIS】本命 Job（2026-08-26 補正・未検証）

> 「**特に探すものは決まっていないが、東京の面白いものを少し見たい。
> 見ているうちに、行く／詳しく見る対象が生まれる。**」

- **目的地探索型に限定しない。** 起点は「探す」ではなく「**見る**」。
- 意図（行く・詳しく見る）は**入口に存在しない**。閲覧の途中で**生成される**ものとして扱う。
- したがって **Browse / Entertainment Value 自体が Pilot の検証対象**（第 11 節 V0）。

### 【HYPOTHESIS】副次 Job（従来仮説・併存させる）

> 「今週末／今日、東京で"ちょっと変なところ"に行きたい。でも自分では思いつかない。」

- こちらは**目的地探索型**。本命 Job の**下位ケース**として残す。
- 検索は**行き先が決まってから**使う道具であり、**行き先を思いつく**道具ではない。
- Instagram は**知人と映え**の軸で並ぶため、「変だが実在する」対象は流れて出会えない。

### 【DECISION】Job の扱い

- 本命は browse 型。**Official Action に到達しない閲覧も、失敗ではない**（第 1 節 価値候補 A）。
- どちらの Job が主かは Pilot で判定する。**現時点でどちらかに実装を最適化しない**。

- 一方で「既知対象は『次を見る』で流される」。
  → **未知性が Job の核**である可能性を示唆するが、Founder 1 名の反応であり一般化できない。

### 【FACT】現時点で Job 検証に使えるデータ

## 3. Why not Instagram / Pinterest / Google Maps / AI

| 比較対象 | 相手が強いところ | 当店が別物である理由（【DECISION】） |
| --- | --- | --- |
| **Instagram** | 人と繋がる。映えの流通。母数と速度。 | 反応が**人のタイムライン**に積まれ、**人気**が可視化される。当店は反応を**対象側**に積み、followers / likes / ranking を持たない。person-centric にしない。 |
| **Pinterest** | 視覚的即時性。大量の発見。 | **infinite feed × popularity optimization** が中核。当店は**有限・Human-curated な棚／特集**にする。Visual Immediacy は**参考にするが、無限化と最適化は採用しない**。 |
| **Google / Maps** | 網羅性。営業時間・経路・口コミ。 | **行き先が決まっている人**に最適。「何を見に行くべきか」は返さない。当店は**問いの前段**を担い、事実確認と Action は公式・Maps に**渡す**（競合しない）。 |
| **AI（生成・推薦）** | 無限の候補生成。個別最適。 | **実在性と権利の保証がない**。当店は Human Editorial が承認した実在対象のみを扱い、生成物を置かない。「あなたに最適」も出さない。 |

### 【FACT】この差別化が現実に成立しているかの現状

- 監査（`V3_REAL_MEDIA_EDITORIAL_FIRST_PULL_AUDIT_20260826.md`）の結論:
  会期のある展示 3 件で**終了日・入替・休室が未表示**であり、**Google 検索のほうが正確**という逆転が起きていた。
  → **差別化以前に、事実の正確性で負けている領域が存在した**。これは思想ではなく実装の欠落。

## 5. Discovery Loop

### 【DECISION】構造

```
有限の棚／特集（Human-curated・タイトルが「なぜ横並びか」を説明する）
  → Real Media（一覧でも実写真・実動画）
  → Hook（短い・説明しない）
  → タップ
```

- 特集タイトルは**編集の宣言**であり、分類ではない。
  例（Founder 提示）:「一個に振り切りすぎた東京」「普通のカフェじゃ物足りない東京」「大人になってからやると変なこと」
- **有限**であること。末尾があり、「ここまでです」で終わる（既存の完了画面の思想を継承）。

### 採用しないもの（【DECISION】）

infinite feed ／ popularity optimization ／ hidden profiling ／ engagement maximization ／
followers ／ likes ／ popularity ranking ／ streak。

### 【HYPOTHESIS】検証が必要な点

1. 特集タイトルが「なぜこれらが横並びなのか」を**実際に説明できている**か。
   - 【EVIDENCE】Entry Test 01 Variant B で「単なるカルチャー一覧に見える」「なぜ新宿御苑とチームラボが横並びなのか伝わらない」（Founder 観測）。
     **タイトルによる解決は未検証の仮説**。
2. 有限であることが「物足りない」ではなく「信頼できる」と受け取られるか。
3. 一覧で Real Media を並べたときのスクロール挙動（有限だが縦に長い）が成立するか。

## 6. Experience Detail Loop

### 【DECISION】構造

```
Hook（一覧から引き継ぐ・同じ言葉）
  → Reveal（「どういうこと？」の答え。Human Editorial の切り口）
  → Verified Fact（公式確認済みの事実。時間・料金・会期・場所）
  → Official Action（公式ページ / 予約 / 地図）
```

### 設計上の拘束（【DECISION】）

- **Hook は一覧と Detail で同一の言葉**であること（別の言葉にすると「押した理由」が消える）。
- **Reveal は Hook に答える**こと。棚の説明・感情の説明・推薦理由を Reveal に混ぜない。
- **Verified Fact は出典を持つ**こと。確認日を保持し、期限切れは fail-closed で落とす（既存 freshness 契約を継承）。
- **Official Action は 1 つを主**とする（既存 Action Destination 契約: primary 1 件＋補助）。

### 【FACT】既存実装との差分

- 現行 Detail は `Identity → FIRST PULL → Editorial Why → Official Fact → Official Action` の順で、
  **構造としてはほぼ一致している**。欠けているのは中身（Hook / Reveal の承認本文）であって、構造ではない。
- 【EVIDENCE】ただし Founder 観測では「長文はほぼ読まれない」。
  現行の `placementReason` は 100 字前後で、**Reveal としては長い可能性がある**（未検証）。

## 8. Object-centric vs Person-centric

| 軸 | Person-centric（Instagram 型） | **Object-centric（当店・【DECISION】）** |
| --- | --- | --- |
| 蓄積先 | ユーザーのプロフィール／タイムライン | **Experience / Work object** |
| 主語 | 「誰が投稿したか」 | 「**この対象がどう受け取られたか**」 |
| 可視化される量 | followers / likes / 人気順 | **持たない** |
| 新規性の源 | 人のネットワーク | **Human Editorial の切り口** |
| 失敗モード | 人気の集中／演者化／承認欲求の最適化 | 対象の**在庫が薄いと即座に枯れる** |

### 双方向 graph（【HYPOTHESIS】として保持）

```
1) One Emotion        → Many Experiences / Works
2) One Experience/Work → Many Human Emotions

   Emotion ↔ Experience / Work ↔ Human Response
```

- 原則: **「感情が動きそうなものを置いているが、どう動くかは本人次第」**（【DECISION】）。
- 【FACT】現行 registry は 1) の片方向のみ実装（`OUTING_RELATIONS` / `COLLECTION_RELATIONS`）。
  2) を実装するにはデータモデルの追加が必要で、**今回は設計判断のみ・実装しない**。

### 【HYPOTHESIS】object-centric の最大リスク

person-centric は「人が増えると勝手にコンテンツが増える」が、
**object-centric は編集が止まると増えない**。
→ 東京 Pilot は同時に「**Human Editorial が供給を維持できるか**」の検証でもある（第 11 節）。

## 10. Human Editorial の役割

### 【DECISION】編集部が担う 4 つ

1. **選ぶ** — 何を置き、何を置かないか。「有名だから」「人気だから」を理由にしない。
2. **切り口を作る** — 対象の説明ではなく、**知らなかった見方**を一つ立てる。
3. **横並びの理由を作る** — 特集タイトルとして、なぜこれらが並ぶのかを言語化する。
4. **事実に責任を持つ** — 出典・確認日・権利を保持し、期限切れは落とす。

### 編集部が担わないこと（【DECISION】）

推薦アルゴリズムの代行／人気の反映／ユーザーごとの出し分け／感情の断定。

### 【FACT】編集の品質基準は既に運用されている

- 監査基準として「A: 自分では探さなかった対象との出会い」「B: 知っている対象の知らなかった見方」を採用し、
  「有名／人気／公式サイトにある／感情棚に合う」だけでは KEEP にしない運用を実施済み。
- その結果、8 件中 **KEEP 6 / KEEP IF REAL MEDIA 1 / WEAK 1**。

### 【FACT】編集の供給能力は未実証

- Hook 承認本文は **8 件中 0 件**。
- 新規 6 件（DAWN / スネークセンター / 筋肉女子 / 忍者 / 食品サンプル / おもちゃ美術館）の Hook は
  **検証用仮 copy** であり Production 承認ではない。

| V5 | **編集の供給が続くか** | 1 特集あたりの制作コスト（対象選定＋事実確認＋権利＋Hook）を実測 | 部分的に判明（第 10 節） |
| V6 | **有限であることが不満でなく信頼になるか** | 末尾到達時の反応 | 未実施 |

### 【DECISION】Pilot の暫定設計（2026-08-26 追加）

**1 cycle = 外部初見 12〜18 人**。**原則 2 cycle** で判断する。

主指標（primary）:

| 指標 | 定義 |
| --- | --- |
| **Object Open** | 提示された特集から、**自発的に 1 件以上の対象を開く** |
| **Return Desire** | 「**また新しいものを見に来てもよい**」に相当する**行動または回答** |

副指標（secondary）:

| 指標 | 定義 |
| --- | --- |
| Official Action 率 | 公式ページ／予約／地図へ進んだ割合。**重要指標だが Kill 判定の単独根拠にしない** |

**暫定 GO 目安**

- Object Open **60% 以上**
- Return Desire **40% 以上**

**暫定 Kill / Pivot 目安**（2 cycle 後も次の 3 つが**同時に**成立する場合）

- Object Open **40% 未満**
- Return Desire **25% 未満**
- かつ「**Instagram / Google / TikTok 等で十分**」が多数で、**固有の利用理由が出てこない**

【HYPOTHESIS】これらの数値は**暫定**であり、外部データを持たない状態での設定である。
1 cycle 目の結果を見て閾値自体を見直す余地を残す。

### 【DECISION】測り方の拘束

- 「良いと言われた」ではなく**行動**を優先して見る。ただし Return Desire は回答でも可とする。
- 個人プロファイリングは行わない（集計のみ）。**GA4 の定義変更が必要になった時点で別 Gate**。

## 13. Kill Criteria

【DECISION】以下に該当したら、**その方向を止める**（改善で粘らない）。
※ 暫定閾値は第 11 節に定義済み（2026-08-26 追加）。本節は**判定軸**を定義する。
※ **Official Action 未達は単独の Kill 理由にしない**（第 1 節 価値候補 A を維持するため）。

| # | Kill 対象 | 判定条件（案） |
| --- | --- | --- |
| K1 | **Hook 方式そのもの** | Real Media + Hook を出しても、初見が Detail を開かない（V1・V2 が連続して失敗） |
| K2 | **Reveal 方式** | Detail を開いても Reveal が読まれない／読まれても「で？」で終わる |
| K3 | **Official Action 接続** | **単独では Kill 条件にしない**（2026-08-26 補正）。Object Open と Return Desire がともに閾値未満で、かつ固有の利用理由が出ない場合にのみ Pivot 判断に含める |
| K4 | **編集供給** | 1 特集の制作が現実的な工数・期間で回らない。または**事実確認で落ちる率が高すぎる**（※ 前回計上した「6 件中 2 件不採用」は誤判定に基づくため撤回。第 10 節参照） |
| K5 | **権利** | Real Media の権利取得が**構造的に不可能**（対象カテゴリの大半で許諾が下りない） |
| K6 | **object-centric 前提** | 反応を対象側に積む設計に、ユーザーがそもそも反応を残さない（第 7 節の検証時） |
| K7 | **名前と体験の乖離** | 「感情書店」という名から入った人が、実際の体験を別物だと感じ、説明コストが恒常的に発生する |

### 【DECISION】Kill しない理由にしてはいけないもの

「Founder が面白いと思うから」「もう作ってしまったから」「もう少し磨けば」。

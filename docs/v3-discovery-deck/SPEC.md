## 1. 現行実装との差分

方針10項目に対する現状。

| # | 方針 | 現状 | 対応 |
|---|---|---|---|
| 1 | 1画面に1候補を大きく | すでに実装済み | 変更不要 |
| 2 | 横スワイプ / 矢印 / ドラッグ | **swipeは実装されていたが動作していなかった** | RCで修正済み。矢印は未実装 |
| 3 | カードが少し重なり次があると分かる | 未実装 | 在庫3件化と同時に入れる |
| 4 | 0〜3件の有限候補・無限スクロールなし | すでに実装済み（`1 / N` counter） | 変更不要 |
| 5 | 現物優先ラダー | tier3/tier5が稼働、tier1/2/4は権利未確認でfail-closed | 権利確認後に別task |
| 6 | カード上は最低限の情報 | RCで一行の公式導入を追加し充足 | 変更不要 |
| 7 | 詳細は公式説明→なぜこの棚→実用情報→公式Action | RCで実装済み | 変更不要 |
| 8 | Action語を感情書店の言葉へ | すでに「気になる」「今回は違う」「詳しく見る」 | 変更不要 |
| 9 | 相性%・人気順・いいね数・マッチ演出なし | 一切存在しない | 維持 |
| 10 | 人を評価しない / 世界との接点を編集する | 維持されている | 維持 |

**結論**: 方針の大半はすでに満たされている。実質的な未実装は #3 の重なり表現と #2 の矢印だけ。

## 2. RCに入れたもの

`attachSwipe` の2つの不具合を修正した（詳細はRC結果を参照）。

- card全体で `setPointerCapture` していたため、card内buttonのclickが発火しなかった。
  desktopでは「詳しく見る」「気になる」「今回は違う」「公式Action」が全て無反応だった。
- card上の画像がネイティブdragを開始し `pointercancel` で横スワイプ判定が失われていた。

結果として **左スワイプ=今回は違う / 右スワイプ=気になる** が実際に成立した。
方針#2の「横にめくる」はこれで動く状態になっている。

## 3. 次Sprintで入れるもの

### 3.1 重なり表現（#3）

**在庫が1棚1件の間は入れない。** 1件しかない状態で背後にカードがあるように見せるのは、
存在しない候補を示唆することになり、0/1/2/3が全て有効という契約に反する。

Editorial在庫が1棚3件になるタイミングで同時に入れる。

実装形状（プロトタイプで検証済み）:

```
.slot            position:absolute; left/right/top:0; height:calc(100% - 30px)
depth 0          translateY(0)    scaleX(1)      z-index:3
depth 1          translateY(15px) scaleX(.955)   z-index:2
depth 2          translateY(30px) scaleX(.91)    z-index:1
```

`scale` で等方縮小すると背面カードが前面カードの内側に入り、重なりが見えない。
**縦は translateY で純粋に押し下げ、横だけ縮める。** 背面は最大2枚まで。

### 3.2 矢印操作（#2）

44×44の円形ボタンを左右に置き、間に有限を示すdotを並べる。
- 先頭で「前へ」、末尾で「次へ」を `disabled` にする（無限に続かないことを形で示す）
- `ArrowLeft` / `ArrowRight` でも操作できる
- `:focus-visible` でV3のfocus ringを出す

### 3.3 媒体ラダーの明示（#5）

カード左下に、いま何を見せているかを静かに出す。
「公式提供の実写（写真提供「◯◯」）」／「感情書店のカテゴリー画像」など。
実物を出せていないことを隠さない。権利未確認の画像は絶対に出さない。

## 4. 採用しないもの

方針9の通り、以下は実装しない。

- 相性％ / スコア / おすすめ度
- 人気順 / いいね数 / 閲覧数 / ランキング
- マッチ演出 / 祝祭アニメーション
- 無限候補 / 無限スクロール / 追加読み込み
- 残り時間・在庫煽り等のFOMO
- streak / バッジ / レベル等のゲーミフィケーション

また、これはプロフィールを審査するUIではない。
カードに写るのは人ではなく、世界の側の対象である。

## 5. 見積り

在庫3件化が前提。UI側だけなら小さい。

| 作業 | 規模 |
|---|---|
| 重なり表現（CSS + render時のdepth付与） | 小 |
| 矢印 + dot + キーボード | 小 |
| 媒体ラダーbadge | 小 |
| 回帰（8棚 × 3 viewport の runtime cert 拡張） | 中 |

いずれもRCのcontractを壊さない範囲に収まる。

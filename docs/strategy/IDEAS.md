# 面白くするアイデア — 継続して足していく

ファウンダー指示（2026-09-11）：「サイトとしてさらに面白くなる、見たくなるアイデアは
考え続けてね。」思いつきを並べる場所ではなく、**カタログに実際に何が眠っているかを
確かめてから書く**場所にする。実装済みは印を付けて残す。

判定の基準は一つ。**「有限であること」を弱点でなく便益に変えるか。**
量で勝てる相手（Google Maps、Tokyo Art Beat、ことりっぷ）とは戦わない。

---

## 1. 会場から辿る 🔴 最有力・未実装

**カタログはすでに会場を軸に固まっている。** 気づかずに作っていた。実測：

| 会場 | 作品 | 今の催し |
|---|---|---|
| 座・高円寺 | 映画5本（映画祭の上映作） | **3件** |
| 高円寺JIROKICHI | 本1冊『次郎吉 to JIROKICHI』 | **3件** |
| 神保町シアター | 映画2本 | **3件** |
| 下北沢SHELTER | ライブ音源4曲＋映像1本 | 0件 |
| 吉祥寺 STAR PINE'S CAFE | ライブ音源5曲 | 0件 |

つまり **JIROKICHI の50年史を読み → その場所で録られた演奏を聴き → 今週その場所で
やっている催しへ行く** が、いまのデータだけで一本につながる。

これは `CLAUDE.md` が定義する Cultural Thread と Reality Return そのものである。
「街 → 分類 → 作品 → 外へ」という今の一直線と違い、**作品どうしが交差する**。

必要なもの：作品に会場の構造化フィールド（いまは relationNote の地の文にしか無い）。
編集部が会場を紐付ければ、ページ生成は自動でよい。

**なぜ効くか**：他のどのサービスも「この会場の本・音源・今週の公演」を一枚にできない。
会場は消えないので、催しが会期で消えても、そのページは空にならない。

## 2. 年表 🟡 未実装

作品の年代が読めるのは32/77件、範囲は **1953〜2026年**。街ごとに並べると
「この街の文化がいつ積み重なったか」が一目で出る。

いまは年が `creator` の中の地の文（「犬童一心 監督 / 2008」）なので、構造化が要る。
77件のうち45件は年が書かれていない。**全部埋まらなくても年表は成立する**が、
「一部だけ」を正直に見せる書き方が要る。

## 3. 同じ作品の別のかたち 🟡 未実装・小さい

『森崎書店の日々』が本と映画で2件ある。同じ作品の別メディアは、いまリンクしていない。
`related` を手で書く運用はあるが、**同じ原作から来ているものは機械で見つけられる**。
件数は少ないが、見つけたときの驚きが大きい種類のつながり。

## 4. 今週号 ✅ 実装済み（2026-09-11）

`/discover/weekly/` と `/feed.xml`。「今週で終わる催し」「新しく入った作品」。
**「今週の一本」は置いていない** — どれを推すかは編集部の判断で、生成物が決めない。

## 5. カードに理由と出典 ✅ 実装済み（2026-09-11）

分類ラベル（「映画 · 撮影された街」）ではなく、なぜその街なのかと、その根拠を
一覧の1枚ごとに出す。**差別化は理念ページではなく全クリックで体験させる。**

---

## 却下したもの（理由つき）

- **人気順・おすすめ順・「あなたへ」** — Current Product 定義に反する。議論しない。
- **ログイン／連続記録／バッジ** — 同上。再訪はRSSと編集号で作る。
- **街を増やす** — 4街の補充が回る前に増やすと、空の街が増えるだけ
  （`DIRECTION-20260910.md`）。催しの在庫が先。
- **自動生成の紹介文** — 文言は編集部が決める。生成物が書かない。

## 書き足すときの作法

1. 先にカタログを数える。眠っている材料が無いアイデアは書かない
2. 「有限を便益に変えるか」で判定する
3. 編集判断が要る部分と、生成でよい部分を分けて書く

# 訪問者を増やす：診断と、着実に積む順番

2026-09-11。ファウンダーの指示「サイト訪問者がどうやったら増えるのか戦略を立てて
確実に着実に行ってほしい」への回答。

**先に言っておくべき制約が一つある。私は訪問者数を見られない。**
GA4 に入る認証が無いので、「増えたか」を私が測ることはできない。
だから戦略は、**効果を私が測れるもの**（サイト側の欠陥が潰れたか）と、
**ファウンダーが測るもの**（実際の訪問者数）に分けてある。

---

## 1. 前提：検索に頼る戦略は、もう成り立たない

前の調査（`MEDIA-AI-RESEARCH-20260911.md` §6）で出た数字。

- **小規模な媒体は、検索からの流入を2年で60%失った**（大手は22%）
- 検索の **68%がクリックなしで終わる**
- 各社は今後3年でさらに **43%減る**と見込んでいる

**小さいほど早く効く。** だから「SEOを頑張る」は戦略として弱い。

代わりに三つの柱で立てる。

| 柱 | 中身 | 誰が |
|---|---|---|
| **A. 機械に正しく読ませる** | 検索・AIが引用できる形にする | 私（自動） |
| **B. 戻ってくる理由をつくる** | RSS・今週号。アカウント不要のまま | 私（自動） |
| **C. 人のいる場所へ出る** | X、会場・書店との関係、催し | ファウンダー |

**Cがいちばん効く。** ただしそれは事業判断で、私の領域ではない。
私はAとBを、毎週、確実に積む。

## 2. 診断（2026-09-11 の実測）

## 3. 直したもの（2026-09-11）

### RSS を入口から見つかるようにした（115 → 176ページ）

RSSリーダーはトップページで探す。そこに無ければ、購読されない。
トップ・作品ハブ・催し一覧・作品ページに `alternate` を広げた。

**これがこのサイトの「自分で持つ読者資産」である。**
ニュースレターが最も効くとされるが、メールアドレスを集めることは
外部送信と個人情報の取り扱いであり、端末内保存・アカウント不要という
立て方に正面からぶつかる。RSSを強くするほうが、いまの方針と矛盾しない。

### llms.txt を置いた

AIの回答に入る引用は1回答あたり平均2.8件。そこに入らなければ検索順位は関係ない。
引用されるときに要る前提（人が選ぶ／人気順でない／出典で確かめる／催しに確認日と期限）
を、AIが最初に読む場所へ置いた。

### 催し43件を機械が読める形にした

**これが今回いちばん効く可能性がある。** 催しは日時と会場という、
検索エンジンが構造化して扱える情報を持っている。それを一度も渡していなかった。

書いたのは**持っている事実だけ**である。

- 価格は `practical` に自由文で書いてあるだけなので `offers` にしない
- 画像は会場や街の写真で、その催しの写真ではないので `image` にしない
- 主催者・出演者は構造化して持っていないので書かない
- 住所は持っていない。会場名だけを `Place` に置く

**飛び飛びの日程は `EventSeries` にして、実際の開催日だけを `subEvent` に並べた。**
一つの `Event` に「9/13〜10/17」と書くと、機械はその間ずっと開催していると読む。
『夏の夜の夢』は15日しか公演しない。嘘になる。

内訳は Event 33件 / EventSeries 10件。契約は `qa/event_schema_check.js` が固定し、
`verify-product` が毎回回す。日付・会場・題名が元データとずれたら落ちる。

### 作品77件を機械が読める形にした（2026-09-11）

催しの次は作品である。ページは「WebPage がある」としか言っておらず、
**そこに本があるのか映画があるのかを、一度も渡していなかった。**

種類別に Book 16 / Movie 18 / MusicRecording 20 / VideoObject 23。
書いたのは、催しのときと同じく**持っている事実だけ**である。

- 題名・紹介文・このページの住所
- 公式・一次の行き先を `sameAs`（出版社の書籍ページ、YouTube の当該動画など）

**書かなかったもののほうが重要である。**

- `author` / `director` / `byArtist`。`creator` は「犬童一心 監督 / 田中泯」
  「ドキュメンタリー」「Live Music JIROKICHI 編」のような自由文で、
  役割・会場・年が混ざっている。監督名として型に入れれば、
  「ドキュメンタリー」という名の監督が生まれる
- `contentLocation`（作品の舞台）。街との関係は「物語の舞台」から
  「高円寺の映画祭で上映」まで40通り以上ある。場所として一律に書けば、
  **上映しただけの街を「作品の舞台」だと言うことになる。**
  NO EVIDENCE = NO BRIDGE は構造化データの中でも同じである
- `image` / `uploadDate` / `isbn` / `duration` / 評価・価格。持っていない

サイト内のプロトタイプへ向かう1件（`kichijoji/parks`）は `sameAs` を空けた。
そのページは作品そのものではないからである。

契約は `qa/work_schema_check.js` が固定し、`verify-product` が毎回回す。
**書かないことのほうも固定してある**ので、あとから「もっと書けば有利では」と
足しにきたときに落ちる。

> 断っておくと、Google の動画リッチリザルトは `thumbnailUrl` と `uploadDate` を
> 要求する。23件の映像のうち公開日を持っているのは5件なので、そこは満たさない。
> Search Console の「動画」に不備として出ることがある。**それでよい。**
> 持っていない日付を埋めて通すのは、順位のために嘘を書くことである。

### 街 → 種類 → 作品 の道順を機械に見せた（2026-09-11）

作品ページの eyebrow には「高円寺 / 本・漫画 / 街が名前を変えた小説」と出ている。
**読者にはずっと見えていた階層を、機械には一度も渡していなかった。**

`BreadcrumbList` を97ページに置いた。作品77・種類16・街4。

- 作品：街から探す → 高円寺 → 本・漫画 → 高円寺純情商店街
- 種類：街から探す → 高円寺 → 本・漫画
- 街：街から探す → 高円寺

**書かなかったページのほうが判断が要った。** 記事・会場・特集・今週号には書いていない。
親が一つに決まらないからである。無理に親を決めれば、**読者が通っていない道を
機械に教えることになる。** 検索結果のパンくず表示は、読者が押す前に見るものなので、
実在しない道を出すのはリンク切れより悪い。

契約は `qa/breadcrumb_check.js` が固定する。名前が合っているかだけでなく、
**各段の行き先が実際にファイルとして在るか**まで見る。道順の一段目が消えたら落ちる。

### 行き止まりと孤立ページを調べた（2026-09-11）

`AUTONOMY-20260911.md` §6 層1 が挙げていた二つ。**探した結果、直すものは無かった。**

`qa/orphan_page_check.js` を作った。配信面185ページを**実際にブラウザで開いて**、
そのとき出ているリンクを数える。静的に `href` を読むだけでは、JS が後から足す
リンクを見落として「行けるページを行けない」と言ってしまうからである。

結果。

- **本文から次へ行けないページ：0件。** 共通ヘッダのリンクは数えていない。
  それを数えると、全ページに付くので行き止まりは永遠に0件になる
- **どこからも行けないページ：12件。全部 `noindex` だった。**
  役目を終えた URL を 404 にせず残してあるもの（`outings/solo.html` など）で、
  **これは欠陥ではなく正しい扱いである**

#### 最初は2件を「欠陥」と書いた。私の道具が間違っていた（同日訂正）

`atlas/index.html` と `explore.html` を「検索に載せるつもりなのに行けない」として
報告したが、**どちらも `noindex,nofollow` が付いていた。**
道具が `content="noindex"` の完全一致で探していたので、
`noindex,nofollow`（このサイトに51ページある）と `noindex, follow`（2ページ）を
見落としていた。

`atlas/` はさらに `vercel.json` で `/thread.html?thread=koenji-dance-history` へ
リダイレクトされている。**本番ではその URL に留まることすらできない。**

直したのは道具のほうである。robots の値をカンマで分けて `noindex` を探す。
**既知として持っていた2件の一覧も消した。** 例外ではなく、読み違いだったからである。
いまは例外ゼロで ORPHAN_PAGE_GO になる。

### 回っていないテストを回した（2026-09-11）

45本のうち `verify-product` が回していたのは22本。残り23本を全部走らせて、
main と突き合わせた。内訳はこうだった。

- **通るのに誰も回していない：11本。** ここが穴である。今週の自分の回帰
  （`seo_check`）はまさにここに隠れていた
- 承認済み再設計で守るものが無くなったもの：3本
- ブラウザ・ネットワーク・参照先コミットが要るもの：9本

**環境に依らず速い9本を `verify-product` に入れた。22本 → 27本。**
全体で3.5秒しか増えない。入っていなかったのは、ただ誰も入れなかったからである。

入れられなかった2本のうち `works_browser_qa` は**本物の指摘を持っている**。
main でも落ちる。上の「編集判断が要る」1番がそれである。

### 同じ場所へ行くリンクを二つ並べるのをやめた（2026-09-11）

`works_browser_qa` が main でも落ちていた指摘。`works.html` と `work-book.html` の
本のカードに、出版社の同じページへのリンクが2本あった。表紙の出典表示
（`書籍情報 ↗`）と、現実側への行動リンク（`出版社で本の紹介を見る`）である。

**出典表示は権利の要件なので消せない。行動リンクは Reality Return なので消せない。**
そこで、**リンクにするかどうか**を分けた。同じ行き先が既にそのページの行動リンクに
あるときだけ、出典表示を文字だけにする。credit の文
（『神保町の怪人』紀田順一郎／創元推理文庫（東京創元社）／装画：影山徹／装幀：山田英春）は
そのまま残るので、**出どころは消えていない。** 行き先も一行下にある。

街の作品カードは変えていない。あちらは出典が行動リンクと別の行き先を指すことがあり
（4件中2件がそう）、そこでは二つ目のリンクに意味がある。

### ついでに直した回帰（自分が入れたもの）

先週 `robots.txt` に「なぜAIクローラーを閉じないか」のコメントを足した。
`qa/seo_check.js` が robots.txt を1バイト単位で固定していたので、これが落ちていた。
**`seo_check` は `verify-product` が回さない25本のうちの1本で、誰も見ていなかった。**
契約を「命令は allow-all と Sitemap の二つだけ、ブロックは一つも無い」へ移した。
コメントは通り、`Disallow` を足せば落ちる。守るものは変えていない。

## 5. やらないこと

訪問者を増やす手段には、この製品では使えないものがある。
**数字が上がっても、製品が別のものになるなら採らない。**

- **人気順・ランキング。** `CLAUDE.md`「Popularity ranking ではない」
- **無限スクロール・自動再生・通知。** `CLAUDE.md`「Infinite Feed ではない」
- **連続記録・バッジ・ゲーミフィケーション。** Guardrails で明示的に禁止
- **読者の行動から属性を推定して出し分ける。** 「Psychological profiling ではない」
- **釣り見出し。** 文言は編集部のもので、数字を根拠に変えない
- **量で埋める。** `SELECTION-20260910.md`「枠を埋めるために基準未満を残さない」

CNET は量を目的化して、77本中41本に訂正を出した。
**増やす速さより、間違えない速さのほうが遅い。** 遅いほうに合わせる。

## 6. 効果をどう見るか

私が測れるのは「穴が塞がったか」までである。訪問者数はファウンダーが見る。

**私が毎週測るもの**（`qa/` と週次の点検）

- 催し・作品の構造化データが元データと一致しているか
- 押しても何も起きないリンクが無いか
- どこからも行けなくなったページ・行き止まりが増えていないか
- RSSが入口から見つかるか
- 在庫が下限を割っていないか

**ファウンダーが見るもの**（GA4）

- 検索・SNS・直接のどこから来ているか
- 公式サイトへ出ているか（Reality Return が起きているか）
- どの街・種類で止まるか

**急がないでほしい。** 構造化データが検索結果に反映されるには、
クロールと評価の時間がかかる。1〜2週で判断しない。

# 選書と映像選定の基準

2026-09-10、ファウンダー決定。棚が「直喩すぎる」という指摘から作った。
既存の `BOOKS-20260909.md`、`VIDEO-EDITORIAL-20260909.md` を置き換えるものではなく、
採否の判断だけを足す。

## きっかけ

本を4冊から増やそうとして20冊を並べたとき、11冊の書名に街の名前が入っていた。
『高円寺純情商店街』『もしもし下北沢』『吉祥寺よろず怪事請負処』——
街の本として集めたのだから当然だが、棚として見ると本の並びではなくラベルの並びだった。
読む前から結論が分かる本は、棚に置く理由が弱い。

## 実際の本屋から採った3点

公開されている記事を読んだ範囲の要約であり、取材はしていない。

- **文脈棚**（往来堂書店）。ジャンルではなく、テーマや文脈でつなげて並べる。
  「この本に興味を持つ人は、隣のこの本も読みたくなるだろう」という納得が棚を成立させる。
- **「迷ったら小さい方」**。分かりやすい大きな一冊より、ニッチな方を採る。
- **セレンディピティ**。確認のためではなく、発見のために置く。

本を輝かせているのは書名ではなく、隣に置く理由のほうである。
これは当サイトが街と作品でやろうとしていることと同じ構造なので、そのまま採る。

## 本の採否

### 採る

1. **書名が街の名前を言わない。** 関係は説明すれば腑に落ちる。
   例：『猫町』（萩原朔太郎／下北沢）、『森崎書店の日々』（神保町）、
   『グーグーだって猫である』（吉祥寺）
2. **書名が街の名前を言う場合は、次のどちらかであること。**
   - **街の側が変わった。** 例：『高円寺純情商店街』。1989年の直木賞受賞を受けて、
     商店街が小説の名を愛称と定めアーチに掲げた。小説が街の名を借りたのではなく、
     街が小説の名を取った。関係の向きが逆である。
   - **その街の文化がどう生まれたかの一次記録である。** 例：『下北沢祝祭行』（LADY JANE店主）、
     『「演劇の街」をつくった男』（本多一夫の語り）、『吉祥寺に育てられた映画館』

### 採らない

- **書名が街の名前を言い、関係が「その街が舞台」だけのもの。** 面白い本かどうかとは関係ない。
  棚に置く理由が弱い。
- 出典で関係を示せないもの。作品の評価が高くても例外にしない。

不採用にした本は `city-discovery-source.js` の `declinedItems` に理由つきで書く。
**未公開には二種類あり、混同すると判断が巻き戻る。**

| 種類 | 意味 | あとで図版が手に入ったら |
|---|---|---|
| `declined` | 編集判断で採らないと決めた | **出ない。** 決め直すには `declinedItems` から外す編集判断が要る |
| `pending` | 図版・予告編が無いだけ。判断は未了 | 公開の対象になる |

2026-09-10 の候補調査で、この5冊が「表紙が無いだけの在庫」として報告された。
コード上そう見えていたためで、判断が文書にしか無かったことが原因である。
いまは `canPublish` が `declinedItems` を先に見るので、表紙が付いても公開されない。

### 評価の扱い

受賞歴・版を重ねていること・書評は、**採否を決めるときの材料**として使う。
順位として表示しない。評価順に並べない。点数を付けない。
`CLAUDE.md` の「Popularity ranking ではない」「人気順で並べない」と両立させるための線である。

### 権利

表紙を複製しない本は、1冊ずつ個別に検討して `textOnlyBooks` へ書く。
一括承認にはしない。著作権が切れていて全文が読める作品は、読める場所へ直接つなぐ。

## 映像の採否

自治体の区・市全体を紹介するプロモーション映像は**採らない**（2026-09-10 決定）。
街への関係が薄く、「関係で選ぶ」という上の基準を自分で崩すため。
既存の『緑あふれるまち 武蔵野市』のように、但し書きで補う形は増やさない。

代わりに、**場所そのもの**の映像へ広げる。公園、映画館、ライブハウス、書店、劇場、
その街で実際に開いている場のもの。「そこがいま何をしているか」が見える映像を優先する。

条件は既存のまま変えない。

- 公開元が明確で、非公開・削除済みでないこと。埋め込みやHTTP応答だけで再生成功としない。
- 街との関係を出典で説明できること。
- 無断の切り抜きを使わない。

## 候補段階での不採用

棚に入る前の候補は、リポジトリに object が無いので `declinedItems` に書けない。
台帳側に「不採用記録」として理由つきで残す。**削除しない。** 同じ候補が次の調査で
また上がってきたとき、理由が無いと同じ検討をやり直すことになる。

2026-09-10 の候補調査で判定した型：

| 型 | 判定 | 例 |
|---|---|---|
| 書名が街を言い、関係が「その街が舞台」 | 不採用 | 『下北サンデーズ』 |
| 書名が街を言い、関係が架空の団体・施設 | 不採用 | 『吉祥寺少年歌劇』。舞台ですらない |
| 書名が街を言い、実際に住んだ・取材した記録 | 採用の対象 | 一次記録にあたるため |
| 関係が「同じ監督」「同じ供給源」だけ | 不採用 | 作品と街の関係になっていない |
| 既掲載と同一の出来事・同一の発信元 | 不採用 | 二重に置く理由がない |

**「その街を論じた本」は、フィクションかどうかで分かれる。** 街の評判を問い直す小説は
物語の舞台であり不採用。同じ問いでも、実際に住んだ記録・取材にもとづく記述なら
一次記録として採る。書名や主題ではなく、**何にもとづいて書かれたか**で判断する。

件数は目標であって、根拠の代わりにはならない。**枠を埋めるために基準未満を残さない。**

## 作業環境からの制約（2026-09-10 時点）

この基準を作った作業環境からは、YouTube、note.com、`city.setagaya.lg.jp`、
出版社サイトのいずれにも接続できない。したがって：

- **新しい映像は、動画IDの実在と公開状態を確認できないため追加できない。**

### 映像を確認する方法

`www.googleapis.com` は遮断されていない。YouTube Data API なら、youtube.com を開かずに
実在・公開状態・埋め込み可否・題名・チャンネル・公開日を確認できる。

環境変数 `YOUTUBE_API_KEY` を設定したうえで、

```sh
node tools/check-videos.js <id または url> [...]
node tools/check-videos.js --catalogue   # 公開中の全59本（街の作品・予告編・短編集）
```

`NG` の行は公開しない。`埋め込み不可` は、動画は存在するが所有者が埋め込みを切っている
状態で、click-to-load の枠では再生できないため、外部リンクとして扱う。

鍵はリポジトリに置かない。環境変数として環境側に設定する。スクリプトは鍵を出力しない。

**このAPIで分からないこと**：そのチャンネルが権利者本人のものかどうか。CMや公式映像の
再アップロードは、実在も公開もしているが権利は不明である。ここは人が判断する。

### 本の出典

同じ理由で、新しい本の出典確認もファウンダーが開いた画面を根拠にしている。
`checkedAt` にはその確認日を書く。確認していない日付を書かない。

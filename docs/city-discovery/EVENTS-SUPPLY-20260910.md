# 催しの在庫 — 2026-09-10 時点の実測と、次にやること

ファウンダーの指摘「街の文化イベントも在庫全然ないよ」を数えた結果。
指摘は正しく、しかも見えているより悪い。

## 何が起きるか

**2026-09-21 に、催しの節が一度に空になる。** 徐々に減るのではない。

原因は会期ではなく再確認期限である。`week.select` は
`e.reviewThrough >= today` で絞り込む。現在の24件は**全件が `2026-09-20`**。
翌日、会期が11月まで残っている展覧会も含めて、24件すべてが同時に表示から外れる。

```
週          件数（その週になったつもりで数えた実測）
2026-09-07  11件
2026-09-14  12件
2026-09-21   0件   ← ここで全部消える
2026-09-28   0件
2026-10-05   0件
```

`qa/event_supply_check.js` は当初これを見落としていた。将来の週を「今日の日付のまま」
数えていたので、期限切れが効かず 3件・2件と出ていた。その週の月曜になったつもりで
数えるよう直した。いまは 2026-09-14 に回した時点で `EVENT_SUPPLY_FAIL` になる
（来週が0件のため）。**空になる1週間前に、ビルドが止まる。**

## 次にやること（安い順）

### 1. 会期が残っている7件を再確認して `reviewThrough` を延ばす

一番安い。新しい催しを探す必要がなく、公式ページを開いて開催が生きていることを
確かめるだけで、7件が戻る。

| id | 残りの開催日 | 会期の終わり |
|---|---|---|
| `kichijoji-taniguchi` | 42日 | 2026-11-03 |
| `shimokita-moon` | 14日 | 2026-10-04 |
| `koenji-midsummer` | 12日 | 2026-10-17 |
| `kichijoji-winter` | 7日 | 2026-09-27 |
| `jinbocho-ginga` | 5日 | 2026-09-25 |
| `jinbocho-pokemon` | 5日 | 2026-09-25 |
| `koenji-cafetalk` | 1日 | 2026-09-24 |

**確認せずに日付だけ書き換えてはいけない。** `reviewThrough` は「この日まで内容の
正しさを保証する」という約束であって、会期の写しではない。確認した日を `checkedAt`
に、次に確認する日を `reviewThrough` に書く。

これをやっても 09-21 の週が7件に戻るだけで、09-28 は3件、10-05 は2件のまま。

### 2. 新しい催しを足す

ここが本体。**1週あたり5件**（`qa/event_supply_check.js` の `FLOOR`）を下限に、
読者が押して満足する数となると10件は要る。

出典の取り方と採否は `SELECTION-20260910.md` と `EDITORIAL-STANDARDS-20260910.md` に従う。
`tools/weekly-outings-source.js` の既存24件が書き方の見本になっている。必須は
`city` `relation` `checkedAt` `reviewThrough` `url`（https）と開催日で、
`build-weekly-outings.js` が欠けを見つけて落とす。

いま催しを出している会場（すべて公式URLが既存カタログにある）：

- 高円寺 — 座・高円寺、高円寺JIROKICHI
- 下北沢 — 本屋B&B、小劇場楽園
- 吉祥寺 — 吉祥寺シアター、武蔵野市立吉祥寺美術館、吉祥寺シルバーエレファント
- 神保町 — 神保町シアター、シネマリス、東京堂書店 神田神保町店

会場は変わらないので、月ごとに同じ10か所を見に行けば在庫はつくれる。
**種類の偏りに注意する。** 現在の内訳は 演劇・舞台8 / 映画6 / 本・トーク12 /
展示・アート3 / ライブ4 で、展示とライブが薄い。トップの「展示」「ライブ」は
ここへ来るので、この2つが読者の離脱点になる。

### 3. 誰がやるか

**この作業環境からは外部サイトに接続できない。** 会場の公式ページはすべて
プロキシに拒否される（`403 to CONNECT`）ので、Claude は催しの実在を確認できない。
確認できないものは書けない（NO EVIDENCE = NO BRIDGE）。

したがって 1 も 2 も、**ファウンダーが開催情報を渡すか、この環境から会場のドメインへ
接続できるようにするか、どちらかが要る。** 情報さえ届けば、カタログへの反映と
ページ生成・検証は Claude 側で完結する。

## 空になったときに読者が見るもの

上の対応が間に合わなかった場合に備えて、`#event-empty` の行き先を足した。
以前は「条件を変えると別の催しを選べます」とだけ書いてあり、全件消えた週には
どう条件を変えても何も出ない案内になっていた。街の作品と作品一覧への導線を置いた。
会期で消えないので、催しが0件でも行き止まりにはならない。

これは対策ではなく、事故のときの受け皿である。催しを足すことの代わりにはならない。

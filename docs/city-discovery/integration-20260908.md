# 2026-09-08 統合修正と次の順序

## 目的
「作品に出会う → 街とのつながりを知る → 想いを残す → また開く」が一つの体験になること。利用枠をほかのプロジェクトとも共用するため、基礎修正を先にまとめ、機能・調査・画像生成を同時に拡大しない。

## 今回の実装
- 作品・催しのスタンプと500文字までのメモを、このブラウザに自動保存。`/saved.html` でタイトル・メモ検索、スタンプ絞り込み、元ページへの復帰、個別解除・直前の解除取り消し。既存「気になる」の街への入口も残す。
- 保存対象のURLから共有トークンとフラグメントを除外。感想はサーバー・計測に送らない。JSON破損や容量超過時に「保存済み」と報告しない。ドメインが異なるPreview／本番・別端末とは同期しない。データの扱いを更新。
- メモの日付を東京の今日で初期化。Googleカレンダーの予定作成、Apple／Outlook用ICSのファイル作成、操作後の案内を一箇所に整理。ICSの実装を維持し、従来の曖昧な「ほかのカレンダー用に保存」を変更。端末側での予定登録完了はサイトから保証しない。
- About、記事、作品、催し、Englishの見出し・余白・ロゴを共通化。日本語の重要な見出しは意味のまとまりで折り返す。Englishの写真はPC2列／スマホ1列で同じ比率にする。古い非対応の日本語メモフォームをEnglish案内から撤去。
- 表紙を別枠のイラストから、路地の奥行きを共有する背景＋HTMLの文字へ変更。架空のイメージであることを明記。写真選択時は実際の街の画像と、その街の作品への入口に切り替わる。
- 天気はアイコン＋短い文字。雨・雪の動きを情景だけに表示し、停止・再開・閉じる・再表示に対応。低モーション設定、画面外、別タブ時に停止。予報／近隣観測値と実況を区別。
- 東京時間の朝5–9時／昼10–15時／夕16–18時／夜19–4時で色を変更。1分ごとと復帰時に更新。夜も本文は読みやすい面を保つ。

## 確認と限界
- ブラウザ：スタンプ・メモ保存、再読込、保存一覧、解除・取り消し、元ページで復元、ICS操作後メッセージ。
- HOME／About／English／保存／記事／神保町の本／催しを320・390・1280pxで計測。横はみ出しなし。About、English、記事、HOMEの見た目を確認。
- 雨と夕方の表示は明示した開発用の模擬データで確認。本物の現地実況を確認した意味ではない。前Previewで気象データが出ていることはユーザーの画面で確認。
- ローカル保存、破損・容量エラー、URL安全性、ICS改行・UTF-8・年越し、東京時間の境界、天気の閉じる・期限切れ・通信失敗などを自動検証。
- 開催日・週切替・キャンセル・絞り込みの既存検証を維持。24件、当週・翌週の各街3件以上という台帳上の条件。これは全イベントの当日の変更確認を意味しない。
- iPhone実機のAppleカレンダー取り込み、Outlook／Googleのアカウント内での予定保存完了は未確認。ブラウザでダウンロードが始まることと、予定が登録されたことを分ける。
- 表紙の人物が歩くCMは未完成。今回の動きは天気の情景演出。マナの完成やライブ接続も報告しない。

## 次の順序と止めどころ
1. この一式を既存Previewへ反映し、iPhoneで保存一覧・カレンダーと文字の見え方を確認。新しい機能より、ここで見つかった不具合を先に直す。
2. 運営確認：公開動画の実再生、週替わりイベントの実際の更新実行と失敗時の挙動、予定終了・取消の除外、出典・確認日の監査。3件に足りない週を架空情報で埋めない。
3. 本番への公開判断。閲覧→再生→保存→再訪／公式案内への移動を利用者の行動で確認。アクセス数だけで成果としない。感想の本文は計測に含めない。
4. 表紙CMとマナの一場面。実際の歩行・接地・表情を確認してから公開。静止画の拡大や揺れを人物アニメーションの完成扱いにしない。新規課金・契約は別判断。
5. 「街のもしも」は別ページで小さく検証。HOMEの主目的を増やさない。初期は人の目線の街路・木陰・看板等を比較。需要を見てから実データとモデルが必要な水害等へ進む。

## カレンダーの根拠

- Apple（iPhone）：https://support.apple.com/ja-jp/guide/iphone/ipha0d932e96/ios
- Microsoft：https://support.microsoft.com/ja-jp/outlook/import-or-subscribe-to-a-calendar-in-outlook-com-or-outlook-on-the-web
Macのファイル取り込み、iPhoneのメール添付からの読み込み、OutlookのICSインポートを区別する。iPhoneでブラウザダウンロードが自動的にAppleカレンダーを開くとは案内しない。

## デジタルツインの採否
- 東京都 https://info.tokyo-digitaltwin.metro.tokyo.lg.jp/ ：地図・建物等と様々なデータを重ねる視点を採用。高円寺の豪雨シミュレーターが既に利用できるという根拠にはしない。
- 大林組 https://www.obayashi.co.jp/kikan_obayashi/detail/kikan_61_hamura_2.html ：人の目線で街を考えることと、目的を先に置くことを採用。立体表示だけを実世界と同期するデジタルツインと呼ばない。
- PLATEAU https://www.mlit.go.jp/plateau/use-case/bz25-01/ ：雨水貯留施設の整備効果を扱う実例。雨量だけでなく地形・土地被覆・排水・貯留等を含む解析の根拠が必要。物体を消した視覚変化から洪水・人流・売上を推測しない。
- 共有された大成建設のページは403、電通総研のカテゴリは本文取得不可。内容を読み込めたとは扱わない。

豪雨を自由に操作する企画は、地理データ・出典・版・ライセンス・解析の検証が揃ってから。先に公式の既定シナリオを表示する案を検討する。単なる雨の背景演出と浸水計算を混同しない。

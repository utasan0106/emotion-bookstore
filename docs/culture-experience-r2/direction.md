## Product definition / DECISION

**街と作品を行き来し、実際に聴く・見る・触れることで、文化のつながりを自分で発見する場所。**

入口を「説明を読む」から「一つの音・場面・作品に触れる」へ移す。Threadは、その後に生まれた「なぜ？」に答える。文章、出典、公式の出口は体験を支える。

「すごい」の核は、派手な都市表示ではなく、知っている曲が実在する街の出来事として聞こえ直すこと。「また来たい」は、気になった演奏をもう一度聴く、新しい編集回に触れる、現地へ行く前後に戻る、という自発的な理由で作る。再訪が増えるかは未検証の仮説。無限再生・ランキング・診断・個人別推薦・通知強制で作らない。

## 最初の一回：下北沢、同じ曲をふたつの演奏で

**FACT**：Boris公式は2007年2月4日のSHELTER公演を『Rainbow』発売記念公演と記す。ライブ盤の3曲目は「Time to Go -夕暮れのジャイロ-」。Pedal Recordsの『SUNSET NOTES』にも同曲がある。出典は `media-provenance.json`。

**EDITORIAL DECISION**：この二つを往復する。共通曲の聴こえ方を利用者自身で比べる。音の差・感情・選曲理由・ソロ盤の録音地は推定して書かない。

**HYPOTHESIS**：ライブ盤を単にリンクするより、会場の写真と演奏を同時に見聞きして、別演奏へ切り替えるほうが、場所と作品の接点を実感できる。

### 体験の絵コンテ

1. SHELTER入口の写真と「同じ曲を、ふたつの演奏で。」を見る。写真は2022年のもので、公演は2007年と区別される。
2. A＝SHELTERライブ、B＝ソロ盤から選ぶ。選択は通信を起こさない。
3. 説明を確認して公式Bandcampプレイヤーを開き、その ▶ で再生する。初回の音まで2操作となる制約を明示する。
4. もう一方を選ぶと前のiframeを破棄して停止する。もう一方のプレイヤーを開いて聴く。自動の同位置シークやクロスフェードはしない。
5. 興味があれば「なぜ、このふたつ？」を開く。最後はSHELTER公式公演情報か下北沢の棚へ。これで一回が終わる。

Native playerのアルバム移動・購入・共有等は提供元の機能として残る。サイトが編集する選択肢は二つだが、提供元の全機能や曲末後の挙動を制御できるとは言わない。

### Visual contract

- Desktop：左に実際の会場写真、右に見出し・2選択肢・一つのプレイヤー。最下部に公演情報への出口。
- Mobile：写真、同曲比較の見出し、A/B、プレイヤーの順。文脈は折りたたむ。自動音声、スクロール固定、ドラッグ必須、装飾波形は無し。
- 素材自体が主役。黒・生成り・濃緑の抑えた配色。音声に合わせたように見せる架空のエフェクトは作らない。
- 説明を読まなくても選択は可能。音を出せない場合にも作品名・演奏者・関係と公式出口が分かる。
- 390 / 430 / 1440、200%表示、キーボード、低速・外部プレイヤー拒否時を公開前に確認する。

下北沢のLADY JANE記録映画は第2段階の映像型を適用する候補。四街同時増産はせず、一つの型が役立つことを確認して展開する。

他の街・文化・時代への接続は、`recorded_at / performed_at / adapted_from / learned_from`等の出典がある関係だけ採用する。「似た雰囲気」は編集上の提案として明示しても歴史的な関係線にはしない。

## 公開前の最小判定

1. 初見の人が5秒で「二つの演奏を聴き比べられる」と理解し、音を出す操作を見つける。
2. 実際の音源が二つとも再生でき、選び直す・閉じるで音が重ならない。再生不能でも公式へ進める。
3. 利用者が写真の撮影年、公演の年、ソロ盤との関係を取り違えない。
4. 説明を聞かずに「音源を聴いた後、SHELTERでの公演が気になった」など具体的な接点を一つ言える。
5. 任意の小規模ユーザーテストで、もう一度使うなら何のためかを聞く。再訪を約束する発言や長い滞在時間だけでは成功扱いしない。

この5項目が成立しなければ、グラフ・地図・大量コンテンツで穴埋めせず、最初の体験を見直す。
